1 · 现状诊断：三个死胡同

A. 课程关卡：路径当成正文
B. 场景城：路径不完整，「查看文档路径」是空气
C. 模块工坊：「进入模块」是伪动作

诊断结论

违反的启发式具体表现
可见性 / 系统状态路径文本呈现了「去哪找」，却无法「点了就去」；用户不知这是文档还是按钮
识别而非回忆用户被迫记住并重打路径，或回到仓库手翻文件夹
匹配真实世界UI 暴露实现细节（相对路径），用户心智模型里不存在「文件系统」
错误预防 / 容错线上站点不部署 lessons/、modules/、materials/，路径是必然 404 的死链
用户控制与自由「查看文档路径」「进入模块」看似动作、实则无功能，打断信任

根因一句话：内容只存在于仓库，不在部署产物里；UI 把「文档链接」降级成了「装饰性文字」。

2 · 设计原则

① 零路径原则
UI 里不再出现文件路径；「读内容」是一等公民动作，一等公民外观（主按钮）。
② 闭环原则
每屏只有一个主 CTA，且指向「下一步学习」：读 → 练 → 测 → 下一关。路径文字只出现在「关于/版权」页。
③ 连续性原则
进入阅读器后，返回应回到唤起点（课/场景/模块）——沿用现有 goPodFromLesson 的上下文返回模式，不打断旅程。
④ 离线同构原则
阅读器内容与主程序同构发布（同域、同 SW 预缓存），断网也能读完。

3 · 目标体验：三条主线

主线 A · 课程关卡（读完就测）

关卡卡片→关卡弹窗→📖 开始学习（应用内阅读器，约 40 分钟）→阅读器内「下一步」→✍️ 课内练习→📝 单元测验→自动勾选 ✓知识点

主线 B · 场景城（先看表达，再开口）

场景卡片→场景弹窗→👁️ 查看素材（表达/对话/角色任务 · 内置页签）→🎮 去演练（演练舱不变）→打卡 + 模块任务联动

主线 C · 模块工坊（读完设备忘）

模块卡片→模块弹窗→📖 阅读模块（4 份文档 · 内置目录）→✓ 自动标记已读→勾选任务清单 / 每日打卡→✍️ 单元测验

5 · 渲染策略：三种方案对比

方案做法优点缺点结论
A · 部署 raw 文件，弹窗里放链接
lessons/ 原样发布 + <a target=_blank>		 改动最小 实现最快 中断心流；离开应用；raw 页面无进度、无返回路径、不计数；仍是「文件思维」 不推荐
B · 应用内阅读器（推荐）
lessons：iframe 内嵌同源 HTML；modules/scenarios：构建期 md→html 预渲染，运行时按卷懒加载		 零路径；进度/打卡/返回闭环；离线同构；复用现有覆盖层体系（pod-mask 同款） 需一个构建脚本 + 少量引擎；iframe 内焦点/滚动需适配 推荐
C · 全部原生重写
把 11 课/12 模块/30 场景逐字重写成 app.js 渲染组件		 完全统一体验 ≈4,600 行内容手工搬运，高风险、低回报 不推荐

6 · 技术实现方案（方案 B）

6.1 目录与构建

repo 根                     onboarding/（部署产物）
lessons/*.html      ──┐
modules/*/*.md        ├─→ scripts/gen_content_viewer.py ─→ onboarding/js/content/lessons/*.html（旁路拷贝）
materials/scenarios/… ─┘                              └─→ onboarding/js/content/mod-*.js / scen-*.js（md→html，按需懒加载）
                                                    └─→ PRECACHE 增：content/ 壳（不预缓存大卷，用到再缓存）
  • Lessons（11 份，≈125KB）：同源 iframe 内嵌（sandbox="allow-scripts"），原页面自带样式/小脚本，零改写；iframe 高度自适应 + 内部滚动。
  • Modules（12 份 README + 44 份 .md ≈256KB）：构建期已转 html → 注入阅读器容器（消毒白名单标签）；每模块一个 JS 卷，ensureModuleContent(id) 懒加载。
  • Scenarios（30 组 × 3 份 ≈396KB）：直接复用 PRACTICE_FULL 已有的 words/phrases/dialogs/tips（应用内已有全量！）；MD 原文作为「查看原文」可选项，默认不加载。Markdown 仅作 fallback。
  • 统一阅读器 #reader-mask：顶栏（← 返回 · 标题 · 进度）+ 内容区 + 底栏（上一份/下一份 · 主 CTA 随场景变化为「下一步：课内练习 / 去演练 / 今日打卡」）。

6.2 状态与埋点（复用现有设施）

  • 阅读完成自动 done.lessonView / 新增 done.contentRead[id]=true → 驱动模块「已读✓」与课程「知识点✓」（替代仅打开即视为已查看的近似逻辑）。
  • 埋点复用 logLearning('content-read', id, pct)；XP 不重复奖励。
  • Escape/遮罩点击/返回按钮三层关闭；#reader-mask 加入现有 document.addEventListener('keydown') 分层链。
  • SW： 每批 bump CACHE（延续 v7 纪律）；阅读器壳进 PRECACHE，内容卷走「首访缓存」。

6.3 测试与门禁

  • 新增 scripts/_test_reader.js（gitignored）：mock iframe 加载、断言章节切换/下一步/返回导航；
  • compat-test.js 追加 3 断言：阅读器可达（Chromium/WebKit/Firefox）、iframe 内容可渲染、Escape 关闭；
  • validate-data.js 增校验：每个 PRACTICE_FULL 场景均有对应素材卷（防「素材缺失」回潮）。

7 · 分批实施计划

批次范围工作量验收点

8 · 风险与对策

风险对策
iframe 内页面样式与主应用冲突lessons/*.html 自带 <style> 且为浅色文档风——天然隔离；统一加 background:#fff 容器即可。
SW 体积膨胀（125+256+396KB）壳预缓存，内容卷一律「首访缓存」；lessons 打包进单卷以摊薄请求数。
Markdown 转换保真（表格/代码块）构建期生成 + audit-content 式 diff 自检；高风险文档人工过一篇。
「已读」判定过于宽松滚动到底部或停留 ≥ 30s 才算已读；配合手动「✓ 标记已读」兜底。
用户断网首开未缓存卷给出友好提示「联网后自动补齐」，不弹错。
